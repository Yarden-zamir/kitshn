How kitshn works

kitshn is a Cloudflare Worker and Durable Object that store your map, plus a small daemon on each of your machines. kitshn writes your map into Cloudflare Access as policies, and Access checks every visit, so opening an app does not go through kitshn.

  • 🗄️

    Control plane

    A Cloudflare Worker and one Durable Object store the map, the rules and all state.

  • 🚪

    Access control

    Circles become Access policies. Cloudflare checks them at its edge on every visit.

  • 🔌

    Machine tunnels

    A daemon on each machine runs your apps and opens an outbound tunnel. No inbound port is needed.

Circles and Access

How circles become Access policies

kitshn does not check visitors itself. It writes your circles into Cloudflare Access, and Access checks each visit at the edge.

🪞

kitshn is the source of truth

A daily check finds differences in Access and repairs them. kitshn names everything it creates kitshn … and does not touch other Access objects.

✂️

Revoking access ends sessions

When you remove someone from a circle or lower a level, kitshn ends their open sessions.

🔁

Tunnels validate the token

A machine's tunnel also validates the Access token, so a wrong DNS record cannot bypass the login.

Data

Where data is stored

Only the recipe is in Git. Access rules are stored in kitshn. Compose app data stays on your machines, apart from encrypted backups in R2.

R2

Access, DNS, routes, tunnels
Generated from the map. kitshn can rebuild them at any time.

The disk

🐙 In your repo

kitshn.config.ts
The recipe: what to build, where it runs, and the circle it starts in. The only state in Git.

Circles and shares are never in Git, so a pull request cannot share your app with someone.
