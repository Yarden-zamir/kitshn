kitshn for enterprise

Every internal app, one map of who gets in.

kitshn deploys your company's sites, Workers and containers from GitHub to your own Cloudflare account and servers. One map decides which teams, contractors, devices and AI agents can open each one, and Cloudflare Access enforces it at the edge.

Why

The sprawl it replaces

Most companies grow internal tools one at a time, and each one brings its own login, its own deploy keys and its own list of who may open it. kitshn puts all of them on one map.

today
  • A VPN or a shared password in front of each internal tool
  • Cloud tokens and deploy keys in the secrets of every repo
  • Servers with inbound ports and a firewall to keep in sync
  • An offboarding checklist that visits a dozen admin panels
  • Nobody can say who shared the dashboard, or when
  • Coding agents run with the keys of whoever started them
→
with kitshn
  • Cloudflare Access at every address, from one map of circles
  • GitHub signs each run, so repos hold no deploy secret
  • Each machine dials out through its own tunnel, so no port opens
  • Take a person out of a circle, and their sessions end at once
  • Every share, move and deploy is a revision with who did it
  • Agents act as their machine, with rights that can ask a person first
Access

Teams, not passwords

A circle is a group: emails, a company domain, an office network, devices, machines, or everyone. A card inside a circle is shared with it. A circle can ask that a person match all its rules, and pass a passkey check after the login.

Cloudflare Access decides this at its edge, from policies that kitshn wrote. The request never reaches kitshn, and never reaches the app when the answer is no.

Taking access away is instant

Lower a level or take someone out of a circle, and kitshn ends their open Access sessions on every application that the circle reaches.

Shares that end by themselves

A share or a whole circle can have an end date, and a card can have an end time, such as one hour for a demo. History names the expiry, and Undo brings it back.

Sign out everywhere

One button ends every Access session of every application that kitshn made. Guests free their seat after a month away, and the Usage view warns at 40 of 50.

Devices and machines are members

A phone, a desktop app or a server proves itself with its own service token, so a circle can let one machine reach another without a person.

Levels per resource

A machine has view, use and control. A circle's level goes on every card in it, a card can override it, and the highest match wins.

Login pages in your look

No bare Cloudflare login: every application gets a kitshn page with the sign-in box under it, and a closed card says so.

Fails closed

Every unknown is a no

A request that kitshn cannot decide gets no access, and the error says why. The design stacks locks so that one mistake, in kitshn, in DNS or in a dashboard, does not open a door.

kitshn is the source and Access is the copy. Everything kitshn makes in Access has a name that starts with kitshn , and it never changes or deletes anything else in your account.

  1. Access at the edge Each private address is an Access application with the policies of its circles.
  2. The tunnel checks again cloudflared drops a request without a valid Access token, so a wrong DNS record cannot skip the login.
  3. Lock on first, off last A new address gets Access, then DNS, then its route. A removal runs the other way.
  4. Lowering never waits A write that removes access retries on a backoff, and the card says Access not lowered yet in red until it lands.
  5. Drift gets repaired A daily compare finds what someone changed by hand and writes it back.
  6. Nobody locks out the admin Every change, also an undo or a pause, is refused if it leaves the admin without a person who passed a passkey.
Deploys

One pipeline, and a gate at every step

A recipe in each repo, kitshn.config.ts, says what the repo deploys. A push to main deploys production, and each pull request gets its own preview that goes away when it closes. On the way, a push passes these checks.

  1. 1

    Signed by GitHub

    The run sends its OIDC token. kitshn takes only the GitHub accounts on its list.

  2. 2

    A repo you allowed

    A new repo waits on the map for one click. Block stops it by its repo id, also after a rename.

  3. 3

    Read, never run

    The recipe is data. A lint refuses loops, conditions and calls, and kitshn never runs repo code.

  4. 4

    A machine you offered

    A container lands only on a machine with the deploy label and the labels it asks for.

  5. 5

    A Compose file that behaves

    privileged, host ports and the Docker socket run only when you allow that repo on that machine.

  6. 6

    Live, in its circle

    A route check, a GitHub deployment status, and the card starts in the circle the recipe names.

AI agents

Let agents ship. Keep the keys.

Coding agents on your machines act as their machine, never as a person. kitshn gives them an identity and short, narrow credentials, and asks a person when you want it to. Agents keep their own tools: git, gh, cloud CLIs.

GitHub tokens for one repo, one hour

kitshn hands out an App token for that repo only. Work shows as kitshn[bot], and no right ever gives Workflows, Secrets or Administration.

Bot pushes never deploy by themselves

A push of the kitshn App waits for a deploy ask, and a pull request waits for a person to press Deploy on that commit.

Passes for your cloud

kitshn is an OpenID issuer. Turn passes on, and an agent gets a 5-minute ES256 pass that AWS or Google Cloud trusts, with no cloud key on the machine.

Approvals with real proof

The approver circle gets a Web Push with Approve and Deny. Approve needs a passkey from the last 10 minutes, and a proposal takes one answer only.

Agents never raise access

An agent change that would share more becomes a proposal. A change that shares less applies at once.

Every ask is on the record

History names the machine, the thread, the action, the reason and the approver, and you search it by label: t3.project.name=billing.

🕰️

History and Undo

Each share, move and deploy is one revision with who made it, kept 90 days. Undo takes back your own newest change, and refuses when a later change depends on it.

📈

Uptime

kitshn checks each app every 2 minutes, puts a DOWN sticker on the map, and keeps a 24-hour strip in the card panel.

🔔

Notifications

A failed deploy, a site down, a machine offline for 15 minutes, a limit at 80%, or a message from the app itself, with Web Push, mute, snooze and quiet hours.

📜

Logs

Search and follow the logs of a container or a Worker from its card, and every deploy run with its output. No log line is copied into kitshn.

🛟

Backups

Every night, restic copies each container app's volumes to R2, encrypted under a key that you keep outside Cloudflare. Restore keeps a copy of now, as the way back.

⏪

Restore kitshn to a time

Rewind the whole map to any point of the last 30 days, with a fresh passkey. A daily state export lands in R2, and you can download it any time.

Machines

A server joins with one code

"Add machine" on the map prints one command with a code that works once, for 10 minutes. The machine downloads a daemon checked against the release's checksums, makes its own key pair and opens its tunnel. Nobody copies a token by hand.

  • One binary for Linux, macOS and Windows, with no Node.js on the machine.
  • Each connection starts with an Ed25519 challenge, and a key rotates in one click.
  • Labels and an order decide where each job runs. A running app never moves by itself.
  • A local dev server becomes a live site at its own address, behind the same circles.
  • When a machine is off, visitors get a friendly offline page, not an error.
Your account

No vendor between you and your apps

kitshn is open source under the MIT license. It runs in your Cloudflare account and on your servers, so your apps, your data and your list of who gets in stay with you.

☁️ One Worker, one Durable Object

All of kitshn's logic and state run in your account. App traffic goes through Access and tunnels, not through kitshn.

🐙 The recipe is all that lives in Git

Circles and shares never go in a repo, so a pull request cannot share your app with someone.

📦 Take your state with you

Download the state export from the Safety panel. The bootstrap rebuilds kitshn from it, and the export holds no secret.

💸 Fits the free plan

The reference setup uses a few percent of each daily Cloudflare limit, and the Usage view shows all of them. A paid plan only raises limits.

Limits

Read this before you roll it out

kitshn writes its limits down. Every requirement in the spec has a number, and every known limit says when to revisit it. Here are the ones a company meets first.

342numbered requirements
58known limits, written down
~800tests, many in workerd with real token checks
  • GitHub user accounts only, for now Deploys trust the accounts on kitshn's list. GitHub organizations are not on it yet.
  • 50 people on Zero Trust Free Access counts a seat per person who logs in. Guests free theirs after a month; a paid Zero Trust plan raises it.
  • One Durable Object One instance holds all state and serializes writes. Plenty until about 10,000 cards on the map.
  • 100 Worker scripts on the free plan Each static or Worker environment is a script, so new previews stop at 90 and name the open ones.
  • Windows runs no containers yet A Windows machine joins, serves live sites and runs agent calls, but not Compose apps.
  • Logs are for the admin In this version, only the admin reads app logs. A circle with Everyone never gets them.
