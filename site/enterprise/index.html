One access policy for every internal app.

kitshn is a self-hosted control plane that deploys your sites, Workers and containers from GitHub, and compiles one map of teams, contractors, devices and agents into Cloudflare Access. Every address is identity-aware. No repo holds a deploy secret. No server opens an inbound port.

The problem

The cost of unmanaged internal tooling

Internal tools rarely fail one at a time. They accumulate: each brings its own login, deploy credentials and list of who may open it, until nobody can state your access posture with confidence.

  • Today

    VPNs and shared passwords in front of tools

    Network location stands in for identity. A compromised laptop or a leaked password reaches everything behind it.

    With kitshn

    Each address is its own Access application, evaluated per request against identity, network and passkey.

  • Today

    Long-lived cloud tokens in repo secrets

    One compromised workflow or dependency can exfiltrate credentials that work until someone rotates them.

    With kitshn

    Workflows authenticate with short-lived GitHub OIDC tokens. Repos hold no deploy secret to steal.

  • Today

    Inbound ports and firewall rules

    Every open port is attack surface, and rules drift from what anyone intended.

    With kitshn

    Machines dial out through their own tunnel. Nothing listens on the public internet.

  • Today

    Offboarding by checklist

    Access outlives employment. Sessions stay valid until a dozen admin panels are all updated.

    With kitshn

    Remove a person from a circle, and their sessions end on every application the circle reaches.

  • Today

    No record of who shared what

    An auditor's question becomes a manual investigation across tools, with incomplete answers.

    With kitshn

    Each share, move and deploy is a revision with its actor and time, kept 90 days.

  • Today

    Coding agents running on personal credentials

    Agents inherit the keys of whoever started them, so a prompt injection acts with that person's reach.

    With kitshn

    Agents act as their machine, with scoped rights and short-lived credentials. Sensitive actions wait for a person.

Security

A fail-closed security model

kitshn fails closed. A request it cannot decide gets no access, and the controls are layered so that one mistake in kitshn, DNS or a dashboard does not open a door.

🔒

Ordered changes

A new address gets its Access application, then DNS, then its route. A removal runs in reverse, so an address is never reachable without its check.

⚡

Revocation does not wait

A write that removes access retries on a backoff, and the card shows Access not lowered yet in red until it lands.

🪞

Drift repair

kitshn is the source and Access the copy. A daily compare finds what someone changed by hand and writes it back.

🛡️

Admin lockout guard

Every change, including an undo or a pause, is refused if it leaves the admin without a person who passed a passkey.

🧯

Bounded blast radius

Everything kitshn creates in Access is named kitshn …. It never changes or deletes anything else in your account.

🔑

Machine identity

A join code works once, for 10 minutes. Each connection starts with an Ed25519 challenge, and a key rotates in one click.

Privacy

Privacy: your data stays in your account

There is no kitshn cloud. The control plane is one Worker and one Durable Object in your own Cloudflare account, so kitshn the project never holds your access lists, your traffic or your data. Your only platform dependency is your existing Cloudflare relationship, and application traffic does not pass through the control plane.

Data Where it lives Control
Access lists, shares, history Durable Object SQLite, in your account Exportable at any time. The export holds no secret.

Deploys

A keyless pipeline, with a gate at every stage

A declarative kitshn.config.ts in each repo defines up to 10 apps. A push to main deploys production, and each pull request gets an ephemeral preview. Repo code never runs inside kitshn.

  1. 1

    Authenticate

    The run presents a GitHub OIDC token. Only allowlisted accounts pass.

  2. 2

    Authorize

    A new repo waits for one approval. A block holds by repo id, also after a rename.

  3. 3

    Parse

    The recipe is data. A lint refuses loops, conditions and calls.

  4. 4

    Place

    Containers land only on machines with the deploy label and the labels they ask for.

  5. 5

    Restrict

    privileged, host ports and the Docker socket need an explicit allowance per repo and machine.

  6. 6

    Release

    A route check and a GitHub deployment status, and the card starts in the circle the recipe names.

AI agents

Built agent-first

Your coding agents can ship on their own. Every machine that joins gets the kitshn command and a skill that teaches it, so an agent can publish, set addresses and read logs without setup, and without anyone handing it a key.

A skill out of the box

Joining a machine installs the kitshn skill, so agents know the commands and the rules from their first run.

Output made for agents

Commands take --json and print one object on stdout, so an agent never parses a screen.

No keys to hand over

Agents act as their machine. There is no token to paste into a prompt or leave in a repo.

Rights you set per machine

Each right is off, automatic, or asks a named circle first. A right you never set asks the owner.

Short-lived credentials

GitHub tokens last one hour for one repo, and cloud passes last 5 minutes, so nothing is worth stealing for long.

Every action on the record

History names the machine, thread, action, reason and approver, searchable by label.
