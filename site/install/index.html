Install kitshn

kitshn runs on your own Cloudflare account, on the free plan. Set it up once, and every repo deploys with a push. Tick each step as you finish it.

What you need

Part 1

Set up kitshn

  1. Make a Cloudflare API token

    Open the token page with the permissions filled in, then click Create Token and copy it. If a permission is missing later, the setup names it and prints this link.

  2. Turn on Zero Trust

    kitshn uses Cloudflare Access for every login. Open Zero Trust in the Cloudflare dashboard once and pick the free plan. The setup stops with this link if you skip this step.

  3. Run the setup

    Pick the admin address on your domain, such as kit.example.com. Replace the values below, then run the command.

    curl -fsSL https://kit.yarden-zamir.com/install | \
  CLOUDFLARE_API_TOKEN=... \
  KITSHN_HOST=kit.example.com \
  KITSHN_OWNER_EMAILS=you@example.com \
  KITSHN_DEPLOY_OWNERS=your-github-name sh

    It creates the Worker, its database, the R2 bucket, the Access applications and the Owner circle. You can run it again at any time: it changes only what is not right, and prints each change.

  4. Add your passkey and open the map

    At the end, the setup prints the admin address and a link to register your passkey. Register it, then open https://kit.example.com. You log in with an email code and the passkey.

Part 2

Deploy your first app

  1. Add a recipe

    Put kitshn.config.ts at the root of your repo. This one deploys a static site. See the recipe guide for Compose and Worker apps.

    import { defineApp } from "kitshn";

export default defineApp({
  static: { build: "npm ci && npm run build", output: "dist" },
  deploy: [
    { on: "push", branch: "main", name: "prod", startsIn: "Everyone" },
    { on: "pull_request", name: "pr-{pr}", ephemeral: true },
  ],
});

  2. Add the workflow

    Put this in .github/workflows/kitshn.yml. It is the same for every app, and the repo needs no secret: GitHub signs each run, and kitshn checks the signature.

    on:
  push:
  pull_request:
    types: [opened, synchronize, reopened, closed]
  workflow_dispatch:
permissions:
  contents: read
  id-token: write
jobs:
  kitshn:
    uses: Yarden-zamir/kitshn/.github/workflows/kitshn2-deploy.yml@main
    with:
      server: https://kit.example.com
    secrets: inherit

  3. Push, then click Allow

    The first push of a new repo waits. Open your map, where it shows "1 repo waiting", and click Allow. The deploy starts, and every later push deploys at once.

    git add . && git commit -m "Deploy with kitshn" && git push

  4. Share it

    The new card starts in the startsIn circle, or in the tray, private. Drag it into a circle to share it. Its address is <repo>.<your domain>.

Part 3, optional

Add a machine

Only needed for Compose apps and for sharing dev servers.

  1. Get a join command

    On your map, click +, then Add a machine. kitshn shows a command with a one-time code that ends after 10 minutes.

  2. Run it on the machine

    Copy the command from the map, or use this one with your code. It installs the daemon and its tunnel as services of your user. The machine needs no Node.js and opens no port.

    curl -fsSL https://kit.example.com/join | sh -s -- <code> https://kit.example.com

  3. Give it labels

    In the machine panel, add the label deploy so that apps may run there, and labels such as docker that recipes ask for in runsOn.

When you need them

More options

Pull request previews

A pull_request entry gives each pull request its own address, <repo>-pr-<n>.<your domain>. It starts private, and goes away when the pull request closes.

Values and secrets

A GitHub secret or variable named KITSHN_<NAME> reaches the app as <NAME>. A secret only for production goes in the GitHub Environment prod.

More addresses

A push entry can list up to 5 addresses. The first one is under your kitshn domain. Others may use further domains that you add with KITSHN_ZONES in the setup.

Share a dev server

Share a dev server of a machine at demo.<your domain>, behind its circles.

kitshn expose 5173 --name demo --dev

Rebuild from an export

"Download state export" in the Safety panel saves your map, cards, circles and settings, with no secret. Run the setup with this value to rebuild an empty kitshn on the same account.

KITSHN_IMPORT=kitshn-state.json
