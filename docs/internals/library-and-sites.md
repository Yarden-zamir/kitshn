# Library, files and sites

The Worker serves pages and files itself, and machines serve live sites through their tunnels. This file holds the rules of the library (K-10xx) and of files and sites (K-11xx).

## Library

- **K-1001** Every HTML page from T3 threads on every machine goes into one library in R2. The provider sends each new `html_render` page to `/agent/library` (K-708), with its thread title, machine and time.
- **K-1002** A new page is private: it waits in the tray (K-509), unless the owner drops it on the map (K-1101).
- **K-1003** The Worker serves a page at `pages.<zone>/<name>` (K-1120) with the sandbox of the T3 render route (no same-origin scripts). Only the kitshn admin host may frame a page or a file (`frame-ancestors`), for the previews of K-520. An id is random, 16 characters or more.
- **K-1004** The Worker checks shares for each page and file request (K-404). A page in "Everyone" opens with no login. Other pages log in through an Access application on `pages.<zone>/login`, and a second one on `pages.<zone>/login/passkey` adds the passkey check. Files use the same paths on `files.<zone>`. Traps:
  - Both applications write the one `CF_Authorization` cookie, and Cloudflare advises against relying on it. So each login path checks the `Cf-Access-Jwt-Assertion` token against its own application, and the Worker keeps it in its own `__Host-` cookie. The audience of the token sets the level, never the cookie name.
  - A logout at the Access logout URL does not end these cookies. "Sign out everywhere" (K-110) does.
  - Each login path marks its return in a 60-second cookie. On a second failure, the Worker answers with the reason instead of a second round, so a login never loops.
  - Only people who can open an item may log in, so a stranger cannot take a seat (K-111). The login applications get copies of the people rules of every circle with an active page, file or admin share, plus the machines policy. The Worker removes every other policy (K-408).
  - A policy goes on a login application only after Cloudflare holds its current body, so a new passkey check is never skipped. The Access sync does not change a copy that a login step still holds.
  - The first run after a deploy fails closed: until the next alarm adds the circle policies, no person can log in to pages and files.
- **K-1005** The Library view lists all pages with a search by title, thread and machine. It reads the index in the Durable Object, not R2.
- **K-1006** Deleting a thread does not delete its library page. "Delete page for good" removes a page or file from R2 and the map at once, without a confirm. Undo cannot bring it back, so the label says so.
- **K-1007** An MCP App page is not shared, because its buttons need its live MCP server. The library keeps it private and says why.
- **K-1008** An import adds all past pages of each machine once. Each imported page is private, as a new page (K-1002), work pages too.

## Files and agent publishing

- **K-1101** "Upload" on the map and `kitshn publish` (K-1116) put a file into R2 and a card into the tray. A file is at most 100 MB. A file dropped onto the map lands where it was dropped, in one revision, so it gets the shares of the circles there at once. An `.html` file becomes a page, and a folder becomes a folder site (K-1129). A drop into a public circle asks first (K-210).
- **K-1102** The Worker serves files at `files.<zone>/<name>/<file name>` (K-1120), with the checks of K-1004.
- **K-1103** Public sites are static sites (K-805) in the Everyone circle.
- **K-1115** An upload of a page or a file gives its card an icon. A page uses the first `<link rel="icon">` with a `data:` URL in its first 256 KB, because a page is one file and a path link counts as no icon. An image file of at most 100 KB is its own icon. The Worker finds the icon before it writes to R2, and deletes the object again when the card cannot be written, so no object stays without a card.
- **K-1116** An agent key publishes a page or a file with `kitshn publish <file>` to `POST /agent/library`. It runs the same upload as a drop, with its limits. Without `--circle`, the card waits in the tray. With `--circle`, it lands in that agent circle of the key at `control` (K-718). With `--public`, it lands in the overlap with Everyone, which needs "shares". kitshn decides the spot again after the R2 write, in the transaction that makes the card, with the pause and K-105, because the rights can change while R2 takes the bytes. A refusal then deletes the bytes. Each output line says who opens the card. `--json` prints one JSON object on stdout.
- **K-1117** A second `kitshn publish` of the same file name by the same key updates its card: same id, address, place, circles and stack. Only that key updates it, and only while it controls the card, or while the card has waited in the tray since it published it. R2 keeps two slots of each item, and the database names the one that serves. An update writes the other slot, and one transaction makes it current, so a failed upload leaves the served bytes as they were. "Restore previous version" switches the slot and copies nothing. One update, restore or delete of an item runs at a time (409 for a second). An update changes no share, so it has no Undo of its own.
- **K-1120** A page or a file has an address name: 3 to 63 characters of a to z, 0 to 9 and inner hyphens. With no name given, kitshn picks a random readable one, such as `calm-otter-42`, from no part of the file, so the address tells nothing about the item. An old name stays with the item (K-1122) and answers with a 302 after the checks of K-1004, so a visitor without access learns no new name. An agent key gets one answer for a missing card and for a card that it may not change, so it learns no names. A rename is a revision with Undo. Known limit: a readable name lets a stranger guess that a private page exists, because the Worker answers with the login, not a 404. Revisit when a name itself is a secret.
- **K-1122** An item keeps its 5 newest old names. A new name past that frees the oldest one. The delete of the item frees all its names. The limit keeps an agent key that renames in a loop from holding many names.
- **K-1123** An agent key publishes a folder as a static site with no repo: `kitshn publish <folder>`. The CLI runs the steps of a repo deploy (K-805) against `/agent/sites/plan`, `…/assets` and `…/finish`. The first publish needs "creates" (K-718), because it makes a Worker script, a hostname and an Access application. It lands as K-1116 says. The same folder name from the same key deploys the same card again, under the rule of K-1117. A plan holds its address and its folder name from the start, so no other plan or deploy takes them. "Remove app" keeps the script, because no repo can build the site again. Limits: 10 folder sites per key (`FOLDER_SITES_PER_KEY`), and no new one at 90 Worker scripts (`SCRIPT_LIMIT`, K-903), because the Free plan stops at 100. Revisit when one agent needs more sites or the account moves to the paid plan. Known limit: a move of a folder site to a new address has no Undo. Revisit when a site needs the Undo of K-1506.
- **K-1127** "Make it a repo": `kitshn repo <card> --repo <owner/name>` makes a new private GitHub repo of a page or a folder site with the user's own `gh` login. So the kitshn App needs no right to make repos, and the first deploy comes from the user's push, never from the App. The CLI asks for a handover (`POST /agent/cards/<card>/handover`), which lasts an hour and holds the address. The first push of that repo id takes the card instead of a new one: same id, script, circles and shares. The repo counts as allowed by the key (K-819) only with that takeover, after every check of the plan. Another repo cannot use the handover, because the GitHub token proves the repo id and the owner id. A page becomes a static site, and its old page addresses redirect to it.
- **K-1129** The owner uploads a folder as a folder site from the map, by a drop or from "Upload…". The browser cannot call Cloudflare, so it sends the files through kitshn (`/api/sites/plan`, `…/assets`, `…/upload` in parts of at most 40 MB, `…/finish`). kitshn forwards a part only for an open plan and only with files of its manifest, and keeps the upload token to itself. The browser leaves out every file and folder that starts with a dot, such as `.git` and `.env`. Known limit: the upload token lives in memory, so a restart during an upload ends it. Revisit when uploads often outlive a restart.

## Live sites and the offline page

- **K-1104** A live site is a local server of a machine, shared through the tunnel of the machine at `<name>.<zone>`. `kitshn expose` or `kitshn_expose` adds it, and `kitshn unexpose` removes it. kitshn makes its card, DNS record and ingress only when nothing else uses the address, and its DNS record and ingress only after its Access application exists. It is live only: when the machine is off, the site is off. `--time` gives the card an end time (K-212), and `--circle` places it by the rules of an agent upload (K-1116).
- **K-1105** A live site of a dev server gets the `Host` header `localhost` toward its origin, because Vite and similar servers refuse other hosts.
- **K-1106** When the origin of a live site or a Compose app is down, visitors who pass Access get the kitshn offline page: status 503 with `Retry-After: 60` and `Cache-Control: no-store`, served from the Worker's static assets with no call to the machine. It has one "Knock again" button, and no animation and no automatic reload.
- **K-1107** kitshn detects a down origin in two ways. The machine is off: its daemon socket closes, or misses pings for 30 seconds. kitshn checks at least every 2 minutes (K-1302). The machine is on, but the local server is off: the daemon tries each exposed site every 10 seconds and reports a change.
- **K-1108** While an origin is down, kitshn adds a Worker route for the site address. When the origin is back, it removes the route. So a visit to a healthy site never runs the Worker. Custom error rules would do this with no Worker, but the free plan has none.
- **K-1109** While the route exists, the Worker first passes the request to the origin, and shows the offline page only for status 502 or 530, or a Cloudflare 1033 error. So a site that comes back before the route goes works at once.
- **K-1110** The Worker reads the site name and the last seen time from the Durable Object, and keeps them for 60 seconds in the Cache API.
- **K-1131** The live site wizard takes what the owner has at hand: `5565`, `localhost:5565`, a URL or a socket path, and shows what kitshn understood. The running servers of each machine (K-619) are one click each. `POST /api/sites/live` is one service that only makes new sites, and queues `kitshn expose --new` on the machine (K-614). With Private, the new card waits in the tray. With a circle, it lands there when it arrives. kitshn keeps who asked and the circle by job id, so the end runs as that owner (K-1506), and a failed job drops both. Known limit: this lives in memory, so after a restart the end runs as the machine and the card stays in the tray.

## Domains, icons and redirects

- **K-1111** kitshn publishes only on zones that the owner adds. The zone of `KITSHN_HOST` is the kitshn zone. The bootstrap adds further zones with `KITSHN_ZONES` and checks DNS read access on each. kitshn finds the zone of an address by its name, the longest zone first. A broken `KITSHN_ZONES` leaves only the kitshn zone (K-006).
- **K-1112** A static or Worker deploy takes the site icon from the built files: each `<link rel="icon">` of `/index.html`, then `/favicon.ico`, then the web manifest icons. The `kitshn deploy` step picks it, because only Actions has the bytes. Known limit: kitshn ignores `<base href>`. Revisit when such a site shows the wrong icon.
- **K-1113** kitshn keeps one icon per site, page and file card in the Durable Object, and writes it only when its bytes change (K-1302). An icon is at most 100 KB and one of PNG, ICO, GIF, JPEG, WebP or SVG, by its first bytes. The Worker serves it at `/api/icons/<card id>` only to a visitor who opens the map, with a sandbox content security policy, so an SVG runs no script on the admin host.
- **K-1114** The daemon reads the icon of each Compose app and live site through the site's own target only: its socket or its localhost port. A link counts as no socket. Reads are small and spread out, so a machine with many apps does not stall. The Durable Object takes an icon only for a site that the machine reports, and changes it at most once an hour, so a daemon cannot use up the rows written (K-1302). It takes no icon from an unsigned connection (K-1708).
- **K-1124** An old address of a site card sends its visitors on with a 302 to the main address, with the path and the query. One Worker, `kitshn-redirects`, serves every old address from a map. An old address keeps an Access application with the card's policies, so only who may open the card learns where it went. The alarm does this work, not the deploy, so a deploy stays inside its subrequests (K-406). A card keeps its 5 newest old addresses (K-1122).
- **K-1128** "Add redirect address…" adds a hostname that only redirects to the card's main address, through the same `kitshn-redirects` Worker and with the checks of K-817. So a hostname that another server answers today moves only after its record goes. A redirect address counts toward the 5 of K-1122, but a rename never pushes it out. Remove is the way back, with no Undo.

## Login and refusal pages

- **K-1130** No Access application that kitshn makes shows the bare Cloudflare login. Each one shows a kitshn login page with the Cloudflare sign-in box under it: "chef" for Owner-only cards, "closed" for a card that lets nobody in, and "login" for the rest. The pages change only what a visitor sees, never who gets in. A login page allows no script, so it cannot hide the sign-in box. The bootstrap makes the three pages and passes their ids as `KITSHN_LOGIN_PAGES`. They need the token permission "Account > Access: Custom Pages > Edit". Without it, the applications keep the Cloudflare login.
- **K-1132** A person whom no circle lets in gets a kitshn page, not the Cloudflare "no access" page. The Access sync gives each card application a `custom_deny_url`. Rules:
  - The application `kitshn ask for access` of `kit.<zone>/ask` takes only the people policies of the circles that share cards, never Everyone, so no stranger takes a seat (K-111).
  - `/ask` shows the refusal with "Ask for access", which opens one `access` notification for the owner (K-1904). The ask grants nothing.
  - `/public/help/denied` is for a person whom no circle knows. It says to ask the person who sent the link.
  - Both pages name the owner by the zone, never by an email. "Open it again" shows only for an https `original_url` on the zone, because the query is the visitor's.
  - The help pages run no script. The Access custom page templates need a paid plan, but the redirect URL does not.
  - Known limits: Access does not pass the refused email, and one-time PIN sends no code to an email that no policy allows. Revisit when Access passes the email.

## Public lists and badges

- **K-1118** `GET kit.<zone>/public/cards.json` lists the public app cards that are up: a push deploy, not offline, stopped or failed, and shared now with an "everyone" circle that matches "any". During a lockdown (K-1504) the list is empty. Only this path and the badges have a Bypass application. It answers any origin, because the data is public. The edge caches it for 5 minutes. Trap: browsers get `Cache-Control: no-store`, because the zone's Browser Cache TTL raises every lower `max-age`. Known limit: icons are inline, so the answer grows with each card. Revisit when it passes 500 KB.
- **K-1119** `GET kit.<zone>/public/badges/<owner>/<repo>.svg` draws a deploy badge from the newest deploy of that repo, app (`?app=`) and environment (`?env=`, default `prod`). Every other case draws the same `unknown` badge, so a badge never shows that a private app exists. Every other path below `/public/` is not found, so the Bypass applications cover only badges and `cards.json`. A fault draws `unknown` with status 200, so an image proxy shows no broken image.
- **K-1121** The repo gate keeps the workflow file of the waiting push run, from the `workflow_ref` claim of its OIDC token. Allow (K-819) starts that file again, such as `kitshn-site.yml`, not always `kitshn.yml`. A token without the claim, or with a file of another repo, keeps `kitshn.yml`. A pull request run records no branch, so Allow does not start it.

## Uptime

- **K-1125** kitshn knows whether each app and live site card is up. A Compose app or a live site fails while its daemon's site check says so or its machine is offline. kitshn fetches each address of a static or Worker site without a login: a status of 500 or higher, or no answer in 10 seconds, is a failure. A card goes down when it still fails 5 minutes after its first failure, counted by time. One success makes it up. So a short error, a deploy or a reconnect never makes a card down. Known limit: a private site answers with the Access login, so a private app that fails behind Access counts as up. Revisit with a check that passes Access, if needed.
- **K-1126** The alarm checks uptime once per 2-minute turn, at most 8 addresses per turn, inside the 40 calls of the run (K-406). The daily run fetches none, so it keeps 10 subrequests spare. With no daemon connected, uptime wakes the Durable Object at most every 10 minutes. kitshn keeps a row only for a card that is down or failing, so a turn where every card is up reads no row. Each fetch of a Worker app is a Worker request of the account.
