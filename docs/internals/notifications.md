# Notifications

One notification system serves every source. This file holds its rules (K-19xx).

- **K-1901** A notification has a source (for example `uptime`, `deploy` or `kitshn.ask`), a key that is unique within its source, an optional card, recipients, a level (info, warn, error), a priority (normal, high), a title of at most 100 characters, a text of at most 500, actions and a state. A source opens, changes and closes a notification through the same source and key, so a key that is still open makes no second notification. Any state other than "open" closes it. Known limit: so a source state that must stay open, such as "asked, waiting", needs a separate field. kitshn keeps notifications for 30 days, at most 500.
- **K-1902** The owner gets every notification except `kitshn.ask`, which goes only to the people of the approver circle of its proposal. The live asks of the snapshot follow the same rule: a subject gets only the asks that it may answer (K-1723, K-1727). Other members get no app, uptime or deploy notification. Known limit: the notification routes sit behind the admin check (K-104), so a member of an approver circle cannot reach them yet. Later: a circle can turn on the notifications of a card for its members, never through a circle with "everyone".
- **K-1903** The Durable Object service has three calls for every source: open or change a notification, set its state (an answer closes it for all recipients), and register an action handler per source. A "run" action calls the handler after kitshn checks that the caller is a recipient. A "link" action opens a map path, which runs its own checks. A source writes a row only when its notification changes (K-1302).
- **K-1904** Sources: `deploy` (the newest run failed or did not run), `uptime` (K-1125), `app` (K-1908), `limits`, `machine` and `alarm` (K-1910), `kitshn.ask`, `update` (K-628), `provider` (K-704), `health` (K-631), `repo` (K-819, with "Allow" and "Block" as run actions) and `access` (K-1132). kitshn derives `deploy` and `uptime` from the state that it keeps anyway, so no deploy step needs a call of its own.
- **K-1905** The Notifications view lists the notifications of the last 30 days. The bell counts open notifications that are not info, muted or snoozed. An open info notification closes itself a day after it opened, so it needs no Dismiss. Ways out: "Dismiss" closes one, and the same source and card open a new one only for a new episode. "Snooze 1 h" hides one, and "Unsnooze" shows it. "Mute" hides one card and source for a time or until "Unmute". Mute, snooze and dismiss never answer a notification of a source with answers. A push without answers has "Dismiss" where Android has room for a button. Only an ask sends a push when it closes (K-1907), so when the Notifications view opens, it closes each push of its browser whose notification the list has closed, if the push showed before the list was read. Known limit: until then, a phone keeps the push of a closed notification, such as "X is down". Revisit if stale pushes confuse.
- **K-1906** A notification writes 1 row when it opens and 1 when it closes, and a mute or snooze 1 row. The reconcile after each change reads only the open notifications, from memory after the first read. The view reads at most 500 rows, only while it is open.
- **K-1907** Web Push, because it needs no third party, costs nothing, and works on Android once the map is installed. Rules:
  - The Durable Object makes the VAPID key (P-256) on first use and keeps it in `meta` under `push_vapid_jwk`, out of every read path, export, backup, snapshot and History entry. kitshn adds no encryption of its own, because it has no store key (K-809). "Rotate push key" deletes every subscription, because a subscription belongs to one key.
  - A subscription belongs to one browser of one person, with its levels (warn and error by default) and quiet hours. During quiet hours only "error" and priority high get through.
  - A push goes out when a notification opens, and for priority high when its state changes. Never on close, dismiss or snooze, and never for a muted card and source.
  - The payload is encrypted end to end (RFC 8291) and holds the title, source, card name, id, map path, state, the proposal id of an ask, and the ids and labels of run actions. Never an address, a reason text or a secret. The service worker reads more, such as the text of an ask, with the browser's own login.
  - A button of a push acts with the login of the browser that shows it, through the same routes and checks as the map: run actions (K-1903) and Dismiss with the admin login, Approve as K-1722 says. VERIFY: Chrome on Android asks for an unlock before it runs a button of a notification on the lock screen.
  - The alarm sends the pushes that wait at the end of its run, at most 5 and priority high first, so a run stays at 45 of the 50 subrequests (K-406). A new open notification of priority high, such as an ask, also goes out at once from the request that opened it, at most 5, because an agent waits on it. Inside the alarm it waits for the end of the run. A state change, such as the answer to an ask, waits for the alarm, because its request may have spent its calls already. Known limit: a wake drops the pushes that wait. Revisit if pushes get lost.
  - A 404 or 410 deletes the subscription. A 401 or 403 keeps it and logs a warning, and "Rotate push key" is the way out.
  - kitshn takes any https push endpoint, because only the owner adds one. Revisit with a list of push hosts if other people can add devices.
- **K-1908** App events. Each deploy, redeploy and rollback gives the app a new notify token and `KITSHN_NOTIFY_URL`. A Worker app gets them as secret bindings. A Compose app gets them in the environment of each service, and the token stays in no file, log or job row. kitshn keeps only the SHA-256 of each token, and the newest 6 tokens of good runs per card, so a rollback brings back a build whose token works. Rules:
  - The app sends `POST /notify` with `Authorization: Bearer <token>` and `{title, text, level, key?, resolved?}`, at most 4 KB. The path has a Bypass application, and the Worker checks the token. A token opens only its own card.
  - Limits: 10 calls per card per hour, and 30 per hour for all cards, so one app cannot starve the others. Known limit: the counts live in memory. Revisit if an app or a stranger floods.
  - The push of an app event says only "<card> has news", never the app's title or text (K-1907).
- **K-1910** kitshn's own sources. `limits`: once an hour, never in the daily run, a usage value at 80% or more of its limit opens a notification, which closes under 80%. `machine`: a machine offline for 15 minutes. `alarm`: a step of the alarm that throws (K-406), keyed by step. kitshn keeps the failing steps in `meta`, so a restart keeps their backoff, and a dismissed notification stays closed while the same failure lasts.
