# Game servers

A game card gates the ports of a game server on one machine with doors: one door opens the ports for one address of a person. This file holds those rules (K-20xx).

- **K-2001** A game card (kind `game`, level `view`) gates 1 to 4 ports (1024 to 65535, TCP or UDP) of one machine. Its address is `<name>.<zone>` (`join` and `login` are kept names), with a door time from 1 hour to 7 days (12 hours by default) and an optional SRV service. The card does not run the game: any process that listens on the ports is the game, for example a Compose app with the `ports` allowance of K-818. The owner, the CLI (`kitshn game add`) and agents make it, in the tray. A game port may not be a port of kitshn's neighbours (Tailscale `41641/udp`, T3 Code `3773/tcp`), of a kitshn site on the machine, or of another service from the server report (K-619). Known limit: that report lists TCP only. Revisit when it lists UDP. Known limit: the game ports have no DDoS shield, so a flood can fill the line of the whole machine, its tunnel sites too.
- **K-2002** A machine reports the capability `doors` only on Linux with nftables, with the door helper, its sudoers line and its boot unit installed (`kitshn doors install`, as root, once), and with a public address. Otherwise its status names the reason, and a Linux daemon checks again every minute. kitshn keeps the public addresses per game card, so its records stay while the machine is offline. The tools run by their full path, so a root shell without `/usr/sbin` on its PATH works.
- **K-2003** The join page `pages.<zone>/join/<name>` is Worker-checked like a page (K-1004), with no new Access application. It needs a person login, because a door belongs to a person. A home network can leave through another public IPv4 address per destination, so the page also asks address services from the browser and opens each address that it found. A relayed game listens on IPv4 only. Known limit: a network whose route to the door machine uses yet another address still fails. Revisit with a check from the door machine.
- **K-2004** While a game card has an active share in Everyone, its ports are open to every address, with no door: an Everyone game is a public server. Otherwise a door opens the ports for one address until its end: an IPv4 address, or the `/64` of an IPv6 address, because a home gets one `/64` and its devices change address in it. kitshn refuses private, loopback and link-local addresses, and an address that the share check does not allow, so an address condition of a circle holds. A door opens an address, so everyone behind the same NAT (a café, mobile CGNAT) reaches the ports while it is open, and the game's own login stays the second wall. A person has at most 4 IPv4 and 2 IPv6 doors per card, and the oldest closes past the limit. Only a person opens a door, never an agent or a device. Each open and close is a History line.
- **K-2005** The machine holds the doors in the nftables table `inet kitshn_doors`, which only its root helper writes. The game ports drop every packet from no open door in the input, output and forward hooks, so "End now" also ends running connections, and a port that Docker publishes is gated too. Rootless Docker with pasta binds host sockets, so the input hook sees the real client address. `test/doors-netns.sh` sends real traffic through it in CI. Rules:
  - Each door has its end as a kernel timeout, so it closes on time also while the daemon is down.
  - kitshn sends the full plan of a machine after each change and on each connect, also an empty plan, so a card that went while the machine was offline releases its ports.
  - A `flush ruleset` can delete the table, so the daemon writes the last plan again every minute.
  - After a reboot, the boot unit `kitshn-doors.service` loads the last game ports with no door, before the network and Docker start, so the ports start closed.
  - A door closes at once when its person loses the share, when its card or machine goes, and with "End now".
  - Known limit: an Everyone game stays open while its daemon has lost kitshn, also through an unshare or a pause. Revisit if that window matters.
- **K-2006** The owner reads each game card with its doors and problems (`GET /api/games`), closes any door, and removes the card. An agent whose circle controls the door machine does the same for that machine's games, and needs "adds apps" to remove a card.
- **K-2007** kitshn makes DNS-only A and AAAA records of each game card to the public addresses of the door machine, and an SRV record for the first TCP port. It never adds to a record that it did not make. The alarm spends at most 4 calls a run on them (K-406).
- **K-2008** A game on a machine without a public address goes through a relay machine that has one, TCP only. The game machine's tunnel serves `<name>-relay.<zone>` to `tcp://localhost:<port>`, behind an Access application that lets in only the relay machine's service token. The relay runs `cloudflared access tcp` on that port, so its door table gates the relay like a local game. UDP games behind NAT need another way, such as WireGuard. Revisit when one is needed.
