# Login and Access

kitshn has no login code. Cloudflare Access logs people in, and kitshn compiles its shares into Access. This file holds the rules for identity (K-1xx) and for enforcement (K-4xx).

## Identity and login

- **K-101** Cloudflare Access does every login. kitshn has no login code and no password store.
- **K-102** People log in with the Access One-time PIN (an email code) or with GitHub. The passkey check of K-103 applies after either method.
- **K-103** A circle with "needs passkey" asks for a passkey or a security key after the login, through Access [independent MFA](https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/independent-mfa/).
- **K-104** kitshn administration is a resource of kind `kitshn.admin` with the level `control`. Its card sits in the Owner circle, which has "needs passkey" on.
- **K-105** kitshn refuses every change that leaves the admin resource without a share to a circle with at least one person and "needs passkey". The guard runs on every write: a drag, a circle edit, an undo, an agent tool and the pause (K-1504). It also refuses a share of the admin resource with an "everyone" circle, because that circle compiles to an Access Bypass policy.
- **K-106** A device proves itself with an Access service token, one per device. A device is a circle member like a person.
- **K-107** A machine proves itself to Access with its own service token (K-602), and to kitshn also with its own key pair (K-1704). A machine is a circle member too, so a share can give one machine access to another resource.
- **K-108** kitshn has no browser approvals of the machine map. A passkey or a device token replaces them.
- **K-109** Access sessions of the admin resource last 24 hours. Sessions of other resources last 30 days, unless a circle sets a shorter time.
- **K-110** "Sign out everywhere" ends every Access session of every application that kitshn made, through the Cloudflare API, and never of other applications (K-408). The Worker also refuses page and file logins from before the sign-out (K-1004). History records the start before any Cloudflare call, then the outcome. An application that is left shows in the Access warnings with "Retry sign-out". A retry revokes only the applications that are left. One sign-out or retry runs at a time.
- **K-111** Zero Trust Free counts one seat per person who logs in, up to 50. So no Access application of kitshn lets in a person whom no circle lets in. kitshn turns on [seat expiration](https://developers.cloudflare.com/cloudflare-one/team-and-resources/users/seat-management/) at 1 month, so guests who stop coming free their seat.
- **K-112** The admin view shows the seats in use, with a warning at 40, and can remove a seat. VERIFY: `PATCH /accounts/{id}/access/seats` turns a seat off.
- **K-113** A person in a passkey circle must reach the App Launcher, because Access enrolls a passkey there. kitshn keeps one policy "kitshn passkey enrollment" on the App Launcher application, from the emails and domains of the passkey circles with "any" match. A circle with "all must match" is left out, because its rules joined with "or" let in more people than the circle does. kitshn never changes another App Launcher policy.

## Enforcement

- **K-401** kitshn compiles shares into Cloudflare Access wherever Access can check them, so a check costs no Worker request.
- **K-402** Each circle becomes reusable Access policies: one for its people (Allow, with the passkey check), and one for its devices and networks (Service Auth). Access lets service tokens and logins without a person in only through Service Auth. A resource with an address becomes one self-hosted Access application, whose policies are the circles that hold it. The account limits are 500 applications and 500 reusable policies.
- **K-403** A resource inside "Everyone" gets a Bypass policy, or no Access application.
- **K-404** The Worker checks shares itself for what it serves: pages and files. It reads the Access JWT and the visitor IP. Its only own cookies hold the Access tokens and the return mark of the login steps (K-1004).
- **K-405** A provider enforces levels inside its own program, from the grant table that kitshn gives it (K-706). Access still guards the address and lets in every circle with a level above none.
- **K-406** kitshn writes Access changes from a Durable Object alarm queue. One alarm run makes at most 40 Cloudflare API calls, because the free plan allows 50 subrequests per request. kitshn counts each call before it starts. Each step of the run is isolated: a step that throws logs the error, opens an `alarm` notification (K-1910) and backs off (5 minutes, doubling, at most 1 hour). The other steps still run. A map change ends the wait of the Access and App Launcher steps, so a lower level still takes effect at once.
- **K-407** The map shows a change at once, and the card shows "applying" until Cloudflare has it. A refusal shows "failed" with the reason and waits for the daily compare. An unclear answer (no answer, a 5xx or a 429) shows "retrying", with a backoff of 5, 15, then 60 minutes. Each retry first reads the object back. kitshn writes the wanted body on any difference and never adopts what Cloudflare serves. A write that lowers access never waits for the daily compare: it retries on the same backoff, also after a refusal, and the card shows "Access not lowered yet" in red. Each map change clears every failed write and its backoff.
- **K-408** A daily alarm compares Access with the shares and repairs differences in what kitshn made. It never changes an Access application or policy that kitshn did not make, and it names such an application when it covers a kitshn address. Exception: on the login applications of pages and files, kitshn removes every policy except its own and the machines policy (K-1004).
- **K-409** A lower level takes effect at once. kitshn revokes the Access sessions of each affected application after the write that took the access away, and providers end the sessions of members that lost a level. When more applications use a policy than one run reaches, the next runs end the rest.
- **K-410** Removal order: kitshn never deletes an Access application while a route can still reach its address (tunnel ingress, DNS record, Worker route, custom domain). It removes and confirms the route, then the DNS record, then the Access application. A failed step stops the sequence and retries after five minutes. A card with several addresses (K-817) runs these steps per address.
- **K-411** An action that a person or an agent starts runs each step as soon as the step before it is done, never at the next periodic run. A step that waits for a time sets the alarm at that time. A step that waits for an answer runs when the answer comes. The 2-minute alarm of a connected daemon (K-1126) is only a retry and a fallback.
- **K-412** Cloudflare's Browser Integrity Check runs before Access, so it refuses a script or a machine for its User-Agent, also with a valid service token. Access guards a private card on every request, so the check adds nothing there. kitshn keeps one Configuration Rule per zone, with the ref `kitshn_private_cards_bic_off`, that turns the check off on each host whose kitshn Access application Cloudflare holds without a Bypass policy. An application of one path does not count. Public cards keep the zone setting. kitshn never changes another rule of the zone. The alarm writes the rule after the Access step, and the daily run compares it again (K-408). The token needs "Zone > Config Rules > Edit", which the token link of K-1202 includes. Without it, the step fails with an `alarm` notification (K-1910), and the bootstrap warns.
