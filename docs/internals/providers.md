# Providers and the local interface

A provider is a program on a machine, such as T3 Code, that adds resource kinds through the daemon. This file holds the rules of the local interface (K-7xx). The wire schema is in `packages/local` (`@kitshn/local`), and the contract tests are in `packages/contract`.

## Local socket

- **K-701** The daemon listens on a local socket and checks the user id of each peer (`SO_PEERCRED` on Linux, `getpeereid` on macOS, through `bun:ffi`). It closes the connection unless the peer is the daemon user or is in `localUsers` of `machine.json`. A peer or a list that it cannot read never passes (K-006). `kitshn local-users` edits the list through the daemon, so the command never writes the caller's own file. Rules:
  - The private socket is in a 0700 folder: `$XDG_RUNTIME_DIR/kitshn/kitshn.sock` on Linux, `~/Library/Application Support/kitshn/kitshn.sock` on macOS. Other users cannot reach it, so the daemon also listens on `/tmp/kitshn-<uid>/kitshn.sock` (0666 in a 0711 folder), where the peer check is the only guard. The daemon uses that folder only when `/tmp` belongs to root with the sticky bit, and the folder is a real folder of the daemon user.
  - A client trusts a shared socket only when the system user `kitshn` owns its folder, because another user can make a folder in `/tmp` under its own user id. Before it sends anything, the client checks that the peer of the socket is the daemon user. Known limit: a daemon whose user is not named `kitshn` needs `KITSHN_LOCAL_SOCKET` for the other users. Revisit when such a machine joins.
  - A user in `localUsers` sends only the agent requests (`status`, `ask`, `forget-token`, `forward`, `job-cancel`, `samples`, `health`, exec, `pong`). A provider user (`--provider`) also sends the provider requests. So a provider such as T3 runs as its own user, and its agents never get root or the machine key. Machine-admin requests answer "not allowed" unless the caller is the daemon user or root. A new request kind must name who may send it.
  - Trap: Bun gives the descriptor of a connection only in its undocumented `fd` property. Without it, the daemon refuses every peer. So CI compiles and runs `packages/daemon/src/peer.selftest.ts`, and `.bun-version` names the one Bun of CI and of the release build.
- **K-702** The socket speaks JSON lines: requests with an id, answers with the same id, and events with no id. The schema is Effect Schema in `@kitshn/local`, attached to each edge release as `kitshn-local.tgz` (K-723). The daemon checks each message and names the problem of a bad one. A line longer than 65,536 characters ends the connection. A reader skips an answer or event of a type that it does not know, so a new event never breaks an older client.
- **K-703** The interface pushes events. A provider subscribes once with `register` (K-704) and gets its events on that connection. Events carry no provider name, because one connection holds one provider. Nothing polls.

## Provider protocol

- **K-704** `register` names the protocol (`protocol: 2`), the provider, its stable `instance`, its kinds, its commands and all its resources. A `register` replaces what an earlier one named, so a provider restart needs no cleanup. Rules:
  - The same instance replaces its old connection. Another live instance of the same provider is refused.
  - The provider belongs to the connection that registered it. When the connection closes, the provider and its cards are offline. kitshn opens a `provider` notification after 5 minutes offline.
  - A provider name belongs to the user id of its first accepted `register`. `kitshn providers rebind` moves it to another provider user, and the cards stay the same. Windows binds no user (K-621).
  - One bad resource, row, fact, sticker or client never refuses a `register` or an `upsert`. The daemon drops it and names it in `problems`. Only a broken shape refuses the whole `register`. The daemon and kitshn check these rules with the same code (`reportProblem`).
  - Limits: 8 providers and 500 provider cards per machine, 20 kinds and 40 commands per provider. Reserved names: `kitshn`, `site`, `repo`, `machine`, `page`, `file`.
  - `kitshn provider` joins its stdin and stdout to the socket, so a provider needs no socket code. The daemon pings every 15 seconds and drops a connection that sent nothing for 45 seconds, and the provider does the same to the daemon.
  - "Forget provider" removes every card of an offline provider as one revision with Undo. kitshn refuses it while the daemon reports the provider as running.
  - kitshn takes a provider report only on a signed connection (K-1704).
- **K-705** `upsert` adds or replaces resources, and `remove` removes them by id. A resource with a site (a local port) becomes the live site `<name>.<zone>` of its machine (K-1104), so Access and the tunnel guard it as any card. The card gets that address only after the check of K-1111 finds it free. The owner can take the address over (K-1623). When a report no longer has a card, the card stays offline with its place and shares and no grants, so a provider that registers before its list is complete loses nothing. kitshn never forgets such a card by itself. A status, fact or sticker change is no revision.
- **K-706** For each provider resource, kitshn pushes a grant table to the daemon: each circle with its match mode, its rules, its passkey flag, the provider's name of the level, and the earlier end date of the circle and the share. The daemon decides each level with `check` (K-721), so the provider never reads a table or a JWT. Rules: An actor gives one rule per credential. An agent actor with conditions gives none, and a passkey circle gives no rule of a token, a machine or a network (K-1778).
  - A rule type that a reader does not know never matches, and in an "all must match" circle it fails the grant. So a new rule type never widens access in an older provider.
  - An "all must match" circle that names an unknown machine gives no grant (K-006).
  - The daemon saves the tables and uses them while kitshn is out of reach, so a session still ends at its end date.
  - A pause closes every grant (K-1504).
  - The provider saves the revocations that a lower level or an end date needs, and runs them again until they work.
- **K-707** A provider command is a job of the kind `provider` (K-612), so an offline machine gets it from its queue. It needs `control` on the machine. A command with `confirm` asks first (K-1615). A job waits at most 60 seconds for its provider to register, and 5 minutes for the result.
- **K-708** A provider publishes a page or a file with one `forward` request to `/agent/library` (K-1714). The forwarded body is at most 12 MiB each way. A bigger file needs an agent key.
- **K-709** A resource kind can carry a desired state: a JSON value of at most 64 KB that kitshn stores and pushes to every machine with that provider, without reading it. A value has a shared part and one part per machine, and each machine gets only the shared part and its own. A provider may send a JSON Schema of the value, so the map can edit it with generic controls. kitshn does not validate a value against the schema: the provider validates what it applies. A provider never puts a secret in desired state, because an agent reads it with "reads" (K-1730). History records each change, without Undo. `desired-init` writes a part only when it is absent, atomically with owner edits; an empty object is present. A distinct message type makes older daemons and Workers refuse initialization without writing. kitshn checks the kind against the last provider report, so the daemon sends a waiting report before it forwards `desired-set` or `desired-init`.
- **K-710** A local round trip takes under 5 ms. A change on the map reaches a provider in under 1 second when its machine is online.
- **K-711** The provider holds no Cloudflare credential. Only the daemon holds the machine token and the machine key (K-1702).
- **K-712** The T3 Code fork adds the interface in its own files, with one-line hooks in upstream files. Without the daemon, T3 Code runs as upstream.
- **K-713** T3 Code adds these kinds:

  | Kind          | Levels             | Notes                                                                       |
  | ------------- | ------------------ | --------------------------------------------------------------------------- |
  | `t3.app`      | view, use, control | The T3 apps of one machine. The levels map to the scopes "read", "standard" and "admin". |
  | `t3.thread`   | view, send         | One thread through upstream guest links.                                    |
  | `t3.settings` | none               | Shared settings and themes as desired state (K-709). Not shareable.         |

  A provider kind names its own word for each kitshn level, and a circle level maps to it by K-206. A link from machine A to machine B is B's `t3.app` card shared to a circle that holds A (K-1609). Exec on B is the effect "runs" of A (K-722). The kind `t3.agents` is gone (migration 42). A registration that changes the levels of a kind changes what its shares give, so History records it.
- **K-714** The T3 fork MCP tools have kitshn names: `kitshn_read`, `kitshn_share`, `kitshn_circle`, `kitshn_set_setting`, `kitshn_command`, `kitshn_queue_cancel`, `kitshn_undo`, `kitshn_preset`, `kitshn_join`, `kitshn_resources`, `kitshn_publish`, `kitshn_address`, `kitshn_expose` and `kitshn_deploy`. `machine_exec` keeps its name.
- **K-715** An agent raises access only by the effect "shares" (K-1730). A move of a card that the agent manages into a circle or Everyone follows the caller's "shares": automatic runs, "ask <circle>" waits for that circle, and the default asks the Owner. A change of a circle, a member or a level, and a target out of scope, ask the Owner, whatever "shares" says (K-1778). Each other operation keeps its own effect, such as "destroys" for a removal with no Undo. For agents on a machine, K-1612 applies.
- **K-716** A preset is a saved map layout (circles, members, shares) with a name. An apply is one revision with Undo, runs the guard of K-105, and follows K-715 for agents.
- **K-717** A provider kind can declare per-card settings in `register` (an id, a title, a closed list of values, a default). T3 uses this for the "Update channel" of each `t3.app` card (`nightly` or `daily`). kitshn stores the values outside the card, because each report rewrites the card, and pushes them only to the provider on that machine. A change needs `control` on the card. An agent with `control` changes it with "changes" (K-1730).
- **K-718** An agent key is a token actor (K-1778). An agent on a joined machine acts as its machine instead (K-1710), so a key stays only for an agent on no joined machine (K-1732). Rules:
  - Its agent circles are circles of actors that are not people, with no rule, that name it with a right set, have not ended, do not need a passkey, and that it matches. A circle with a person, a domain, a network or Everyone is never an agent circle.
  - It manages a card that one of its circles holds at `control`, before the kind cuts the level (K-206). `GET /agent/state` shows only those cards.
  - It moves those cards only between its agent circles at `control`, or out of every circle.
  - It runs jobs on a machine only when it manages the machine card, every card on it, and every card that the machine's own token opens (K-107), never by labels. kitshn checks this again when a job goes out.
  - It never sends code itself (K-812). "Redeploy" starts the last good build that the daemon keeps. "Build" dispatches the repo's own `kitshn.yml` workflow through the GitHub App (K-908). Both follow the repo gate (K-819).
  - An agent on a machine stays under these limits only for what runs without a person. A call outside them asks the Owner (K-1776), and the approval runs that one call within 1 hour (K-613).
  - Without an approval of the Owner, it never edits circles, members, stacks, levels, the pause or an admin setting, also with "shares" (K-715, K-1778); the rules of K-105 bind it also then. An agent key deletes no volume; a machine deletes an orphaned volume only by "destroys" (K-909). It removes a page, file or folder site that it published with "destroys", because the removal has no Undo.
  - Its effects are the modes of its chips (K-1720, K-1730): "runs" allows a waiting repo, because the repo then deploys its code; "creates" publishes a folder site and hands a card to a new repo; "shares" publishes a card of a repo that it allowed. Only a member with control on the admin card sets them.
  - A public move takes a card that the key added into the overlap of its agent circle and Everyone, with `POST /agent/apply`, so the key keeps managing it. A live site is never published. The move needs "shares" (K-715).
- **K-719** A provider kind may set `ownerControl` (T3: `t3.app`). Every card of such a kind then has a share of the Owner circle at the top level, wherever it sits, so the owner never locks themselves out of a machine. kitshn adds this share wherever shares count, and refuses an override or an end date on it, like the guard of K-105. A pause closes it like every provider share (K-1504). The local desktop app is the way back in.
- **K-720** A provider may declare client apps in `register` that take a device invite (K-1601), with an `open` link of the app's own scheme. kitshn refuses web schemes (`http`, `https`, `intent`, browser schemes), so no web site gets the invite, and an install link never carries the code. kitshn names no app itself (K-005). Several machines can declare clients. So the invite dialog opens on a client only when every machine declares the same ones, and the public invite page shows only the clients that all machines declare. One machine thus cannot put its own app in front of the owner. Later: Android App Links, which need a certificate field and an exception to K-1770.
- **K-721** The daemon decides access for its providers, so no provider parses Access JWTs or circle rules, and a provider in another language needs no copy of that logic. A provider sends `check` with up to 50 sessions, each with the request headers that the `register` answer names, and gets per session: a subject (`person`, `device` or `machine`) with its levels and `until`, `anonymous` without an Access token, or `refused` with a code. Rules:
  - `expired` needs no revocation. `no-access`, `paused`, `unknown-subject`, `invalid` and `stale` (no kitshn answer for 24 hours) do.
  - `unavailable` (no Access signing keys) starts no new session, but revokes no live one, because the failure says nothing about its token.
  - `until` is the earliest of the token expiry, a grant end and the last kitshn answer plus 24 hours. The provider caches the result until then.
  - `rights` is `["exec"]` for a machine whose "runs" covers this machine at automatic with no conditions (K-722).
  - A change of the grants, the audiences, the pause or those rights sends the provider `grants-changed`.
  - Fail closed: no daemon or no answer means no new session.
- **K-722** Exec on another machine runs through kitshn, streamed, with no link. An agent on machine A sends `exec` with the target B, the command, a folder, a timeout (1 to 3,600 seconds) and its `KITSHN_ATTEST` (K-1751). The answer is `running`, `waiting` with a proposal, or `ended`. Rules:
  - Output flows only within the caller's credit (1 MiB at the start), so the process on B blocks on a full pipe and no hop buffers more. Exactly one `exec-exit` ends the run.
  - The effect is "runs" of A (K-1730). With no mode set, the run asks the Owner, and "off" refuses.
  - kitshn picks the provider on B from the cards that A controls on B, never from A. With several, A names one in `targetProvider`.
  - On B the command runs as the exec user of that provider, never as the daemon user where they differ, because the daemon user holds the machine key. A non-root daemon runs it through one sudo rule for `/usr/local/lib/kitshn/exec`, which root installs with `kitshn exec install`. So a broken provider never blocks a repair. Without the rule, the provider's bridge runs it.
  - Each run starts in `/` with a small environment and its own process group, and no profile runs. A run ends with its main process, and B ends the rest of the group, so a background process never keeps a run open.
  - kitshn keeps each run in a table and relays each frame. An offline B ends the run at once. A daemon without `protocol-2` refuses it. History records each run at its end (K-1610).
  - Known limit: Windows has no process groups, so a kill ends only `powershell.exe`. Revisit when Windows runs exec in use.
- **K-723** One contract test suite covers the provider protocol with a real daemon and no Cloudflare. `packages/contract` holds a fake kitshn edge, a daemon launcher with no tunnel, and the scenarios C-1 to C-18. A scenario waits for events, and a deadline only turns a missing event into a failure. `kitshn-contract --daemon` runs them with the reference provider, and `--provider` runs them against a provider under test. The scenarios that need a second machine, other users or the rollout are covered by other tests, and the command lists these gaps. Each edge release attaches `kitshn-local.tgz` and `kitshn-contract-tests.tgz`, with no registry, so a provider in another repo pins one release.
